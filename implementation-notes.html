1. Toolchain choices

Bun over Node.js + tsup

The original Swift CLI used swift-argument-parser. The initial TypeScript port used tsup + tsx + vitest. We migrated to Bun because:

  • Single binary: runtime, bundler, test runner, package manager
  • Native TypeScript execution without a transpile step in dev
  • bun build produces a self-contained single-file bundle in ~80ms
  • bun test is API-compatible with Jest/Vitest — zero migration friction
  • bun install is significantly faster than npm install

Tradeoff: Bun is not Node.js. Some Node built-ins (e.g. readline used in config init) work but aren't officially Bun APIs. The tsconfig.json uses "moduleResolution": "bundler" and "types": ["bun-types"], which diverges from standard Node tooling. Users on systems without Bun must install it first.

Commander v12 over yargs / oclif

Commander was chosen for its minimal surface area, excellent TypeScript support, and no generated boilerplate. The preAction hook pattern lets global flags (--json, --format, --profile) propagate into a shared OutputOptions object without threading options through every subcommand manually.

Conf v13 for configuration

Conf handles XDG Base Directory compliance automatically and supports schema validation. Profile isolation is implemented on top by constructing a separate Conf instance per profile name, keyed under profiles/<name>/. A module-level cache variable tracks the last-used profile name and resets when GHEALTH_PROFILE changes — important for test isolation.

3. New commands implemented

ghealth devices list|get

Maps to GET users/{user}/pairedDevices and GET users/{user}/pairedDevices/{deviceId}. Returns tracker and smartwatch metadata (manufacturer, model, firmware version, last sync time).

ghealth irn

Maps to GET users/{user}/irnProfile. Returns the user's Irregular Rhythm Notification (AFib detection) consent status and settings. Read-only; requires the https://www.googleapis.com/auth/health.irn.readonly scope.

ghealth subscribers subscriptions-{list,create,patch,delete}

The original CLI only exposed subscriber-level CRUD. Per-user subscriptions live under subscribers/{subscriberId}/subscriptions and are distinct from the subscriber itself. These commands expose the full lifecycle.

ghealth profiles list|current

Lists all named configuration profiles stored on disk and shows which one is active. Profiles are stored in separate Conf stores under profiles/<name>/. The active profile is controlled by GHEALTH_PROFILE or the global --profile flag.

ghealth data import|export|summarize

import reads NDJSON from stdin or a --file path and batch-creates data points. export streams all pages of data in NDJSON format to stdout. summarize fetches a time range and emits aggregate stats (count, min, max, average) for numeric fields.

ghealth auth refresh

Forces an immediate token refresh using the stored refresh token, bypassing the normal expiry check. Useful when the access token was revoked externally but the refresh token is still valid.

ghealth config init

Interactive readline wizard that prompts for clientId, clientSecret, projectId, optional base URL override, and profile name. Writes the result to the active profile's config store.

ghealth agent manifest|capabilities|schema

Machine-readable metadata for AI agent / LLM tooling. manifest emits a structured JSON object describing the CLI name, version, capabilities, output formats, and available date shorthands. capabilities lists every command as a flat array. schema dumps the full data-type registry, scope list, and REST operation table.

4. Feature decisions

Date shorthands (--last)

All time-filtered commands accept --last <shorthand> in addition to --start/--end. Supported values: today, yesterday, 7d, 30d, 90d, Nd (arbitrary days), this-week, last-week, this-month, last-month. The resolver (src/lib/dates.ts) converts these to RFC 3339 timestamps in UTC.

Retry with exponential backoff

src/lib/retry.ts wraps every API call. Default: 3 retries, base delay 1 s, max delay 16 s, jitter ±20%, retry on 429/500/502/503/504. Honors Retry-After response headers. Configurable globally via --retries <n> or GHEALTH_RETRIES.

Auto-pagination (--all)

data list --all uses an async generator (listAllDataPoints) that follows nextPageToken until exhausted. Without --all, a single page is returned so the user controls pagination manually via --page-token.

Named profiles

Each profile is an isolated Conf store. This lets users maintain separate OAuth tokens and config (client ID, project, base URL) for different Google accounts or environments (dev vs. prod). Profile selection precedence: --profile flag > GHEALTH_PROFILE env var > default.

Shell completions

Bash, Zsh, and Fish completion scripts are generated by ghealth completion <shell>. All three scripts are self-contained strings emitted to stdout so the user can source or redirect them. The scripts cover top-level commands, all subcommands, global flags, --format values, and --last shorthands.

5. Architecture notes

Output routing

All output goes through src/lib/output.ts: print(), printError(), printSuccess(). Format selection: explicit --format > GHEALTH_OUTPUT env var > TTY auto-detect (table on TTY, JSON on pipe). This means scripts that pipe ghealth output get JSON by default without needing --json.

HealthClient

src/lib/healthapi/client.ts is a thin wrapper around fetch. Every method calls withRetry(). The client reads config lazily via HealthClient.create() which loads the active profile's stored token and refreshes it if expired. The client does not hold state between commands — each command invocation creates a fresh instance.

Registry

src/lib/registry.ts is the single source of truth for data types, scopes, and REST operations. It drives: types list|get output, agent schema, the data command's type resolver, and the test suite's length assertions. Adding a new data type means one array entry here — no other files need to change.

Error handling pattern

function handleError(err: unknown, o: OutputOptions): never {
  if (isNotLoggedIn(err))      printError({ status: "auth_error", ... hint: "Run: ghealth auth login" }, o);
  else if (isAPIError(err))    printError({ status: "api_error",  message: err.message }, o);
  else                         printError({ status: "error",      message: String(err) }, o);
  process.exit(1);
}

Each command file has a local handleError so errors are routed through the same output formatter as success responses. Machine consumers (scripts, agents) always get structured JSON errors when piped.

6. Tradeoffs

DecisionBenefitCost
Bun runtime Fast, zero-config TS, single binary Not Node.js; some APIs differ; less ecosystem coverage
Single-file bundle (bun build) Easy distribution; no node_modules at runtime Source maps less precise; bundle ~760 KB
Conf for storage XDG-compliant, schema validation, cross-platform Another dependency; file-per-profile approach creates many small files
Local HTTP callback for OAuth No copy-paste of auth codes; standard PKCE flow Requires opening a browser; firewall/WSL environments may block localhost
Retry on 5xx by default Resilient to transient API errors Non-idempotent POST retries could create duplicates (mitigated: only list/get are auto-retried by default)
Flat subcommand strings in completion.ts Simple, no framework dependency Must be updated manually when commands change; could drift

7. Open questions

  • Retry safety for mutating operations: Currently withRetry wraps all client methods. POST/PATCH/DELETE should ideally not retry on network errors (only on explicit 503s with Retry-After). A future improvement is to pass a safe: boolean flag to withRetry.
  • Token encryption at rest: OAuth tokens are stored in plaintext JSON by Conf. On macOS, the system keychain would be a better store. On Linux, libsecret / GNOME Keyring could be used. This is not implemented — the token file permissions are set to 0o600 as a minimum mitigation.
  • Streaming large exports: data export currently buffers all pages in memory before printing. For very large datasets this could exhaust memory. A future version should pipe each page to stdout as it arrives.
  • Subscriptions --all: The subscribers subscriptions-list command does not yet support --all autopagination. Adding it requires the same async generator pattern used in data list.
  • Shell completion drift: The completion scripts in completion.ts are static strings. They will drift as commands are added. A future improvement is to generate them dynamically from the Commander program tree at runtime.
  • Google Health API stability: The v4 API is not yet GA. Endpoint paths, scope names, and data type filter names may change. The registry in src/lib/registry.ts is the only file that needs updating when they do.
